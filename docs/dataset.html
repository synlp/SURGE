Dataset details

A dataset designed to grow beyond a single benchmark task.

SURGE organizes public-event data as temporal signals, aligned text, and interaction structure. This page separates the expanding public collection from the fixed paper-aligned benchmark and defines broader standards for future releases.

Two release views, one evolving data model.

The public explorer prioritizes broad event coverage and readable analysis. The benchmark release fixes a reproducible protocol for model comparison. Their counts and guarantees should not be treated as interchangeable.

Measurements are separated by purpose.

Core observations, derived analyses, and task-specific metrics should not be presented as if they were equally direct or equally permanent.

LayerExamplesInterpretationStatus
Core observationsPost count, event window, bin boundaries, reply/repost edgesDirectly constructed from the released event collection and its canonical preprocessing.Core
LLM-derived labelsPer-post polarity and bin-level Sentiment PolarityReproducible model-derived signals with documented prompts and validation—not gold-standard human labels.Derived

The paper-aligned sentiment series uses Qwen3-32B labels and reports a stratified verification study on 3,000 posts. Expanded releases should continue to publish model, prompt, sampling, coverage, and audit information alongside any new label family.

A broader standard for an expanding dataset.

Future releases should be judged by transparent coverage and data quality, not only by whether they reproduce one paper's forecasting score.

DimensionWhat should be reportedWhy it matters
Coverage and balanceEvent-family counts, platform coverage, active-period range, language availability, and retained versus candidate events.Shows which kinds of public events the collection represents and where conclusions should not be generalized.
CompletenessMissing-bin rate, sentiment-label coverage, text-view availability, graph availability, and unknown-reason breakdowns.Prevents absent labels or artifacts from being mistaken for neutral or zero-valued observations.
Temporal consistencyTimezone, bin alignment, active-window construction, sampling interval, and cross-granularity derivation rules.Keeps event timelines comparable and prevents leakage across time boundaries.
ProvenanceCollection source, query or seed version, pipeline version, transformation history, model and prompt version, and generation date.Makes every published field traceable to the process that produced it.
Label validityAnnotation protocol, audit sample, agreement or error analysis, uncertainty, coverage, and known domain limitations.Distinguishes useful derived signals from universal ground truth.
Graph integrityEdge-type counts, unresolved endpoint rate, temporal validity, duplicate-edge rate, and node/edge coverage.Clarifies whether structural conclusions are supported by complete and valid interaction records.
ReproducibilityImmutable release manifest, checksums, deterministic splits, schema version, loader version, and release notes.Allows an experiment or public visualization to be reconstructed from a named release.
Privacy and responsible useAnonymization rules, excluded identifiers, text-release policy, licensing, intended uses, and misuse boundaries.Reduces re-identification and surveillance risks while keeping the dataset auditable.

How SURGE can grow without losing comparability.

The public collection can expand continuously while benchmark snapshots remain immutable and citable.

01

Stable event identity

New collection passes can add events or artifacts without silently changing existing event IDs.

02

Layered releases

Canonical observations, derived labels, and public analysis should carry separate versions and availability manifests.

03

Immutable benchmark views

Paper-aligned snapshots preserve event lists, splits, targets, and preprocessing even as the broader collection grows.

04

Event-level quality records

Each event should publish completeness, label coverage, graph integrity, provenance, and known limitations.

05

Comparable reporting

Dataset summaries should include macro event results, category slices, missingness, and uncertainty alongside overall values.

06

Explicit deprecation

Schema or method changes require migration notes instead of silently overwriting historical interpretations.

Continue with the data or the events.

The repository remains the source of truth for schemas and code; the public explorer presents the current event-level analysis.
